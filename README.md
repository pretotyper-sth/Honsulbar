# 혼술바

세로형 WebView 미니앱 구현. 실제 출시 전 토스 인증·결제·실시간 서버 연동이 필요하다.

## 실행

`npm install`, `npm run dev`로 웹 미리보기를 연다. `npm run build`는 웹 빌드, `npm run toss:build`는 앱인토스 번들 빌드다. 실제 기기 개발은 `TOSS_DEV_HOST`에 개발 기기가 접근할 수 있는 주소를 설정하고 `npm run toss:dev`로 실행한다.

## 현재 동작

지역 선택, 사진 업로드, 성별 선택, 12석(손님 11 + 중앙 사장 1) 이동, 남은 시간과 음료 메뉴판을 제공한다. 입장 시 500P를 사용하고 고른 음료의 시간만큼 해당 호점에 머문다. 바를 나가면 이용 시간이 끝나며, 다시 입장할 때 새로 결제한다. 입장 전에는 인원만 보이고 500P 미리보기 상품을 구매하면 그 시점의 손님 사진을 확인할 수 있다. 자리 교환은 수락 시에만 요청자에게서 500P를 차감하고 양보한 사람에게 지급한다.

호점 추가, 발화 효과와 음성 입력, 자리 양보 요청, 만석 호점 빈자리 알림 신청을 제공한다. 마이크는 입력 음량에 반응하며 녹음·전송하지 않는다. 사진 업로드와 포인트 등 상태는 주로 메모리에 보관하고 닉네임·온보딩·사진 확인 상태 일부는 브라우저 로컬 저장소에 보관한다. 이웃이 있을 때 빈자리 이동은 확인 창을 거친다.

## 아직 연결하지 않은 기능

토스 성인 인증·로그인·IAP, 실시간 다중 사용자 및 음성 전송, Supabase, 신고 저장 및 관리자 도구. 호점 생성과 입장 배정은 서버의 실제 접속자 상태와 연결해야 한다.

공식 @toss/tds-mobile의 Button·Badge·BottomSheet와 TDSMobileAITProvider를 사용한다. 로비와 시트는 밝은 TDS 스타일이며 어두운 우드톤은 바 공간에만 적용한다. 일반 UI는 Pretendard, 바 간판에만 네이버 마루부리를 사용한다. 예시 얼굴은 randomuser.me의 샘플 사진이며 실제 서비스 가입자가 아니다.

정식 입장은 서버에서 검증한 성인 인증 상태와 좌석 확보·음성 연결 성공 후 시작해야 한다. 포인트·주문·좌석은 서버 트랜잭션으로 처리해야 한다. 현재 입장 전 카메라 확인은 기기 내 얼굴 감지와 사진 유사도 검사이며 서버에서 검증하는 신원 확인이 아니다. 실제 사진 도용은 신고와 사후 운영 검수 절차도 필요하다.

지역은 서울·경기·인천·부산·대구를 잠정 사용한다. 소개팅 앱 점유율 순위로 검증된 목록이 아니다. 지역은 실제 만남 범위이며 동네 인테리어 테마와 다르다.

콘솔 앱 식별자는 `honsulbar`다. 번들에도 같은 appName과 공개 아이콘 URL을 설정했다. 기존 love-alarm의 계정·회원 정보를 자동으로 공유하지 않는다.


## 로비·대화 UX

홈은 호점 선택 후 입장과 빠른 입장을 구분한다. 만석 호점은 선택·유료 미리보기·빈자리 알림 신청을 제공한다. 좌측 상단 잔액으로 포인트 상점에 진입하며 출석 보상·자리 양보·주문·미리보기 내역과 충전 상품, 월 14,900원 정기 구독을 확인할 수 있다. 현재 포인트·결제·구독 상태는 실제 서버나 결제와 연결되지 않는다.

잔 수위는 30분을 가득 찬 기준으로 계산하고 1분 이하에서 옅은 붉은 테두리를 표시한다. 사장 잔은 줄어들지 않는다. 하단 세 좌석도 연속된 곡선으로 배치한다.

대화 방향은 -90~90도이며 반대쪽 음량이 최대 5%까지 줄어든다. 옆자리 전용 대화는 바로 이웃한 손님에게 요청하고 샘플 손님이 2.5초 뒤 수락한다. 전체 대화 복귀·자리 이동·음소거·이용시간 종료 시 해제한다. 두 사람의 양방향 음성 전달 제한은 순수 함수로 정의했지만 현재는 합성 음성의 수신 음량에만 적용되어 있고 실제 사용자 간 음성 전송과 상대방 동의·손 흔들기 전달은 서버 연동이 필요하다. 1·2번 손님은 '옆자리와 대화 중' 상태를 보여주는 예시다.
