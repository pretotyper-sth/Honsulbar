# 혼술바 Android 단독 빌드 체크리스트

작성·확인: 2026-11-01 / 소스: 현재 Honsulbar-AOS 프로젝트

목표: 기존 React 화면·흐름·기능을 공유하고 토스가 제공하던 시스템 연동만 Android용으로 교체한다.
현재 상태: **별도 AOS 폴더·웹 빌드·네이티브 동기화·서명된 debug APK 생성 완료. 실기기 검증·Play 업로드는 미완료.**
테스트 비용: 현재 추가 결제·유료 가입·클라우드 배포 없음. 사용자는 Play 개발자 등록비를 이미 납부했다.

## 1. 지금 적용한 것

- [x] Capacitor 8.6.0 Android 프로젝트 추가. 별도 UI 재구현 없이 같은 `src/main.jsx`, CSS, API, 좌석·포인트·음성 로직 사용.
- [x] Android 테스트용 빌드를 `dist-android`로 분리. 기존 Toss 빌드 경로 유지.
- [x] Android 번들에서는 토스 SDK를 테스트 어댑터로 대체. 토스 결제·로그인·광고 브리지를 호출하지 않음.
- [x] 독립 테스트 앱 ID `com.honsulbar.localtest` 사용. 최종 Play 앱 ID가 아니며, 출시 전 별도 확정 필요.
- [x] 카메라·마이크·오디오 설정 권한 선언. 실제 권한 허용·거부·복구 동작은 기기 검증 필요.
- [x] 기존 테스트 로그인을 재사용. 이는 실명·성인 인증이 아니다.
- [x] 로컬 테스트 계정에만 포인트 모의 충전 구현. 실제 주문·청구·카드·Google 결제 없음.
- [x] 기존 6초 테스트 광고 보상 사용. AdMob SDK 테스트 완료를 뜻하지 않음.
- [x] Android 테스트 서버 별도 생성. `.env.local`을 읽지 않고 클라우드·토스·메일 키 제거.
- [x] 테스트 API 서버는 PC의 `127.0.0.1:3001`에서만 실행. 서버의 외부 fetch 차단.
- [x] DB를 `.local-pg-android`로 분리. 기존 로컬 DB·운영 Supabase 데이터와 분리.
- [x] 모의 충전은 로컬 DB + 개발 로그인 + Android 테스트 플래그가 모두 켜져야 작동. 운영 환경에서 차단.
- [x] Android release 빌드 차단. 현재 모의 연동 상태를 Play 출시용으로 오인하지 않도록 함.
- [x] 전체 자동 테스트 84개 통과. 일반 웹 빌드와 Android용 웹 빌드 통과.
- [x] 390px 브라우저에서 시작·테스트 로그인·로비·포인트 상점·모의 충전(10,000P → 11,000P)·원장 반영 확인. Android WebView 검증과는 별개.

## 2. 0원 테스트 구성

추가 호스팅·SMS·본인인증·유료 음성 중계·결제 대행 SaaS 없이 테스트한다.

- 앱: PC에서 무료 빌드 → 에뮬레이터 또는 USB로 APK 직접 설치.
- API/DB: 기존 PC + PGlite. 무료 체험 종료 후 과금되는 서버를 만들지 않는다.
- 로그인: 로컬 테스트 계정. 실제 회원 인증으로 취급하지 않는다.
- 충전: 로컬 포인트 모의 지급. 실제 결제창·구매 토큰 검증은 후속 작업이다.
- 광고: 기존 모의 광고 보상. 후속 AdMob 개발에서는 Google 테스트 광고만 사용.
- 음성: 기존 WebRTC/P2P. 같은 네트워크에서 우선 검증. 다른 통신사/NAT 환경의 연결 성공은 보장하지 않는다.
- 푸시: 현재 화면 안 알림/대기 데이터만 확인. OS 푸시 수신 완료를 뜻하지 않는다.
- 사진: 기존 로컬 얼굴 비교 모델 사용. 공인 본인·성인 인증을 대체하지 않는다.

**불가능한 약속:** 무료 모의 테스트만으로 실제 본인·성인 인증, 실제 Google 구매·환불, 모든 네트워크에서의 음성 연결까지 검증됐다고 할 수 없다. 해당 기능은 UI를 없애지 않고 연동 완료 항목으로 남긴다.

## 3. 토스 기능별 교체 항목 — 구현은 내가 담당

### 로그인·회원·성인 확인

- [x] Supabase Auth 기반 Google·Kakao 구조 확정. 실제 로그인 성공은 별도 미완료. 공통 DB 유지.
- [ ] Android 앱 ID, 디버그/출시 SHA 인증서, OAuth 클라이언트·동의 화면·테스트 사용자 등록.
- [ ] 서버에서 토큰의 서명·issuer·audience·만료 검증. 클라이언트가 보낸 사용자 ID를 신뢰하지 않기.
- [ ] 기존 `toss_key` 중심 회원키·탈퇴·재가입 보너스·제재 식별자·세션을 공급자별 식별자로 이관.
- [ ] Toss/Android 계정이 같은 사람이라는 연결은 검증 후 처리. 자동 회원 병합이나 포인트 공유 금지.
- [ ] 토스 생년월일·이름 제공을 대체할 **검증 가능한 성인 확인** 설계. Google 로그인 자체는 성인 인증이 아님.
- [ ] 공개 운영 전 필요한 인증 업체·계약·가격 확인. 무료 테스트는 성인 테스터와 테스트 신원으로 한정하며, 자체 체크박스를 실제 인증으로 표시하지 않기.
- [ ] 로그아웃·계정 연결 해제·탈퇴·제재 회피 방지·보존기간·외부 웹 탈퇴 요청 경로 검증.

### 포인트 결제·구독

- [ ] Google Play Billing 네이티브 연동. RevenueCat 같은 별도 유료/사용량 기반 중개 도구는 필수 아님.
- [ ] 기존 5종 포인트 상품의 Play 상품 ID·가격·제공 포인트 매핑. 토스 SKU는 재사용하지 않기.
- [ ] 서버에서 Google 구매 토큰·앱·상품·구매 상태 검증. 포인트 지급 멱등성, 계정 소유권 검증.
- [ ] 지급 후 acknowledge/consume, 중단된 결제 복구, 중복 요청·대기·취소·네트워크 실패 검증.
- [ ] 환불·취소·철회·부정 구매 처리 및 서버 알림 연동. 실제 과금 전에 원장 검증.
- [ ] 구독은 현재 앱의 제공 범위를 유지. 향후 실제 판매 시 갱신·유예·보류·해지·복원·관리 링크 구현.
- [ ] Play **라이선스 테스터** 지정 + 테스트 결제수단 확인. 일반 테스트 트랙에 들어간 것만으로 모든 구매가 무료가 되는 것은 아님.
- [ ] 실제 카드·실제 결제수단으로 구매하지 않기. 테스트 구매만으로 검증.

### 광고·알림·운영 메일

- [ ] AdMob 앱 등록, 보상형 광고 SDK, 동의 처리, 테스트 광고 단위·테스트 기기 설정.
- [ ] 보상형 광고 완료·중도 종료·실패·재시도·중복 보상 방지, 가능하면 서버 검증 연동.
- [ ] 실제 광고 클릭/보상 수익 테스트 금지. Google의 데모 광고로 검증.
- [ ] FCM 기반 Android 푸시 토큰 등록·갱신·삭제, Android 알림 권한·채널 구현.
- [ ] 토스 outbox 발송기를 공급자별 발송기로 분리. 빈자리·문의 답변의 화면/문구/수신 설정 유지.
- [ ] 포그라운드·백그라운드·앱 종료·알림 클릭 이동·중복 발송·탈퇴 후 미발송 검증.
- [ ] 운영 메일은 테스트에서 외부 발송하지 않음. 운영 전 기존 Brevo/Resend 계정과 무료 한도 확인.

### 음성·카메라·기기 동작

- [ ] Android WebView의 카메라·마이크 요청, 거부/다시 허용·카메라 재진입·사진 선택 검증.
- [ ] WebRTC 마이크 입력, 음소거, 방향별 볼륨, 옆자리 전용 대화, 신고 후 연결 해제 검증.
- [ ] 이어폰·블루투스·스피커·전화 수신·다른 앱 전환·잠금·오디오 포커스 검증.
- [ ] 서로 다른 2대, Wi-Fi/이동통신 조합에서 음성 검증. 에뮬레이터 한 대나 합성 손님으로 대체 불가.
- [ ] NAT에서 직접 연결이 실패하면 TURN 필요. 유료 관리형 TURN은 지금 가입하지 않으며, 무료 한도만으로 무제한 운영을 약속하지 않기.
- [ ] 음성 신고 버퍼·동의·암호화·열람 권한·7일 만료 정책을 동일하게 적용하고 Android에서 확인.
- [ ] 뒤로 가기, 상태/내비게이션 바, safe area, 키보드, 화면 회전, 앱 재시작·프로세스 종료 복구.
- [ ] 외부 링크·법적 문서·안전한 URL 이동, 딥링크·로그인 복귀 검증.

## 4. 화면·기능 동일성 검증표

아래는 기존 화면을 공유한다는 것과 별개로 **실제 Android에서 모두 통과해야 하는 항목**이다.

- [ ] 시작 → 로그인 → 프로필 → 사진 동의·얼굴 확인 → 저장 순서.
- [ ] 지역 5개, 호점 인원, 호점 선택/빠른 입장, 만석/다음 호점, 지역 추가 요청.
- [ ] 입장 음료·포인트 차감·입장 실패 시 미차감·남은 시간·퇴장·재입장.
- [ ] 동일한 12석 배치·중앙 사장석·자리 이동·자리 양보 요청/수락/거절/취소·포인트 정산.
- [ ] 전체 대화·방향 조절·옆자리 대화·음소거·시간 만료·강제 퇴장.
- [ ] 손님 미리보기 500P·사진 접근 제한·사진 버전 갱신·차단/신고 후 접근 해제.
- [ ] 잔 수위·남은 시간 경고·시간 연장·음료 메뉴판.
- [ ] 상점·5종 포인트 상품·광고 출석·거래 내역·구독의 기존 제공 상태.
- [ ] 빈자리 알림·문의/답변·신고·차단·이의신청·운영자 화면.
- [ ] 설정·알림 수신 설정·FAQ·약관·개인정보처리방침·탈퇴.
- [ ] 작은/큰 화면·글꼴 확대·스크린리더·버튼 터치·모달 스크롤·다크/라이트 영향을 비교.
- [ ] 같은 상태/화면 크기의 Toss와 Android 캡처 비교. 외부 결제·로그인 제공자 화면은 시스템에 따라 달라짐.

새 탭/메뉴를 추가하거나 기능을 삭제하는 방식으로 이관하지 않는다. Android 시스템 권한 창과 Google 인증·결제창은 제공자 자체 UI이므로 토스 화면과 완전히 같은 모양으로 만들 수는 없다.

## 5. Play 업로드 전 — 내가 준비하고 사용자가 최종 사실 확인

- [ ] 최종 앱 ID·버전·앱 이름, 출시 서명키·안전한 백업. 테스트 APK의 런처·시작 화면에는 기존 혼술바 로고 적용 완료.
- [ ] 테스트 앱 ID·모의 충전·개발 로그인·HTTP API·혼합 콘텐츠 허용을 출시 빌드에서 제거.
- [ ] HTTPS 서버·인증 origin·CORS·운영 DB 접근 제어·요청 제한·비밀키 보관 점검.
- [ ] 개발자 계정 신원·연락처·실제 Android 기기 확인. 현재 사용자는 최근 계정 생성/결제 완료, 기기 확인 미완료.
- [ ] 스토어 소개·스크린샷·아이콘·카테고리·광고 유무·지원 이메일·공개 개인정보처리방침 URL.
- [ ] 데이터 보안 설문: 사진·얼굴 비교·음성·신고 증거·회원 식별자·결제·광고/푸시 SDK 실제 처리 내역 반영.
- [ ] 계정 삭제: 앱 안 경로 + 외부 웹 요청 URL, 보존 예외·기간 안내.
- [ ] UGC/소셜 앱의 신고·차단·모니터링·아동 안전 기준·담당 연락처 점검.
- [ ] 실제 서비스 설명에 맞는 연령 등급·미성년자 차단 적용. 연령 제한 정책은 앱 분류별로 콘솔에서 확인.
- [ ] 앱 접근 안내·심사용 테스트 계정·유료 기능 접근·개인정보가 없는 샘플 데이터 준비.
- [ ] 내부 테스트 → 필요한 비공개 테스트 → 출시 접근 신청. 최근 개인 계정은 원칙적으로 12명 연속 14일 비공개 테스트 요건이 있으며, 실제 적용은 계정 대시보드 확인.
- [ ] 정식 배포 정책의 시행일·버전·HTML/PDF 확정과 기존 release 정책 검사 통과.
- [ ] 서명된 AAB 생성·내부 트랙 업로드·사전 출시 보고서·충돌/ANR·권한·보안 경고 확인.

## 6. 사용자가 직접 해야 하는 일 — 현재 우선순위

SDK 약관 동의·개발 도구 설치는 완료했다. 추가 설치나 결제는 지금 필요하지 않다.

### 지금

1. PC Google/Play Console 로그인 확인 완료. pretotyper 개발자 계정에 접근했고 본인 인증 완료 알림을 확인했다. 실제 Android 기기 인증과 연락처 전화번호 인증이 남아 앱 만들기 버튼이 비활성화되어 있다.
2. 폰을 사용할 수 있는 대략적인 시점을 알려주기. 폰이 오기 전에도 계정 설정·코드 연동·에뮬레이터 검증은 진행할 수 있다.
3. 테스터 모집처에 가입하거나 만 19세 이상 Android 이용자의 참여 의향을 모으기. 이탈 대비 15~20명은 권장 목표이며, Google의 최소 요건을 15~20명이라고 뜻하지 않는다. 지금 APK는 PC 로컬 서버가 필요하므로 실제 설치·14일 테스트 시작은 배포 준비 후 진행한다.

### 폰이 있을 때

- Play Console에서 요구하는 실제 Android 기기 확인을 계정 소유자가 수행한다. 에뮬레이터 실행 확인으로 대신할 수 없다.
- USB 연결·기기 신뢰 및 카메라/마이크 권한을 허용하고, 다른 한 대와 실제 음성 테스트에 협조한다.

### 실제 외부 서비스 연동 시

- 해당 Google/클라우드 계정의 로그인·2단계 인증·본인 확인. 비밀번호나 코드는 채팅으로 보낼 필요 없다.
- 운영자·사업자·지원 연락처 등 사실 정보 확인, 성인 인증 계약이 필요하다면 계약 주체 결정. 유료 계약은 현재 0원 테스트 조건에서 진행하지 않는다.
- OAuth·Billing·AdMob·FCM 코드, 공통 API/DB 연결, 빌드·서명·업로드 준비·스토어 문서 초안은 내가 담당한다.

## 7. 현재 막힌 것과 다음 실행

- Android SDK 약관 동의 완료. 공식 JDK 21·SDK 도구 체크섬 검증, Android 36 플랫폼·빌드 도구·adb 설치 완료. AOS 폴더 내부 `.android-tools`에 설치.
- 일반 `node`/`npm` 명령이 PATH에 없음. 현재 Mac용 `bash scripts/android-local.sh apk` / `server` 실행 스크립트가 설치된 JDK·SDK와 Cursor 내장 Node를 자동 선택한다. 다른 PC에서는 표준 개발 도구 설치가 필요하다.
- Android 빌드용 Temurin JDK 21을 AOS 폴더 내부에 설치했다. 시스템 기본 Java나 다른 앱의 설정은 변경하지 않았다.
- APK 생성 성공: `android/app/build/outputs/apk/debug/app-debug.apk` (약 6.3MB). AAB·실기기 비교·Play 업로드는 미완료. AOSP Android 15 에뮬레이터 설치·부팅·APK 설치·시작 화면 실행까지 확인.
- 실제 외부 로그인·성인 확인·결제·광고·OS 푸시 코드는 후속 연동 작업이다.
- 패키지 설치 결과 보안 경고 6건(중간 4, 높음 2) 보고됨. 상세 audit 요청은 의존성 목록 외부 전송 때문에 자동 승인 검토에서 거부되어 확인하지 못했다. 기존/신규 문제 구분·영향 분석은 미완료.

개발 환경이 준비되면 프로젝트에서:

```sh
npm run android:server
# 별도 터미널
npm run android:apk
# 에뮬레이터/폰이 adb에 잡힌 상태
adb reverse tcp:3001 tcp:3001
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

이 APK는 PC의 로컬 API가 켜져 있어야 동작한다. 외부 테스터에게 APK만 보내면 동작하는 배포본이 아니다. 최종 Play 빌드는 별도 HTTPS 백엔드와 실제 인증 연동 후 생성한다.
