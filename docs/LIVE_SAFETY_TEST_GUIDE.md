# 라이브 안전 기능 시험 가이드

사용자용 요약과 결과 기록은 [OWNER_ACCEPTANCE_GUIDE.md](OWNER_ACCEPTANCE_GUIDE.md)를 먼저 확인합니다.

작성일: 2026-10-24. 동일한 최신 .ait와 API를 운영 환경에서 두 성인 시험 계정으로 검증합니다. 개발 로그인·성인 우회·가짜 가입자는 운영에 활성화하지 않습니다.

## 운영 적용 순서 (담당 에이전트/개발자)

1. 운영 DB가 kwiwpgyzrioygrekpoeg인지 확인하고 백업·기존 회원/포인트 합계를 기록합니다. 20261024_voice_evidence.sql과 20261025_scoped_safety_cleanup.sql을 순서대로 트랜잭션으로 적용합니다. 이전 마이그레이션을 다시 실행하거나 데이터를 초기화하지 않습니다.
2. 서버 전용 HB_VOICE_EVIDENCE_KEY에 32바이트 난수의 64자리 hex값을 설정합니다. 저장소·VITE 환경변수·로그에 넣지 않습니다. 키를 바꾸면 기존 증거를 읽지 못하므로 별도 비공개 보관하고 교체 절차를 둡니다.
3. HB_VOICE_EVIDENCE_ENABLED=1을 설정하고 최신 API/웹을 배포합니다. GitHub의 짧은 유효기간 서명 토큰으로 해당 저장소·main 브랜치·지정 유지보수 작업만 인증합니다. DB 키를 작업에 제공하지 않으며 새 인증키 입력은 필요하지 않습니다. 기존 CRON_SECRET은 유지합니다.
4. GitHub Safety alert retry and evidence retention 작업은 5분 간격을 요청하지만 GitHub 스케줄 지연 가능성이 있습니다. 실제 성공 로그를 확인합니다. Vercel 일일 유지보수는 보조 경로입니다. 새 .ait 업로드 후 기존 버전 대신 새 테스트 스킴을 씁니다.
5. 관리자 화면에서 토스 로그인 설정·메일 설정·음성 DB·음성 보관 상태를 확인합니다. '설정 있음'은 인증 성공·메일 실제 수신을 보증하지 않습니다.
6. 공개 개인정보처리방침·약관·모니터링 HTML/PDF의 같은 버전을 확인합니다. 기존 이용자가 있으면 변경 사전 고지 및 필요한 재동의 절차를 완료한 뒤 활성화합니다.

운영 적용이 미완료인 동안 새 음성 기능이 라이브에서 작동한다고 안내하거나 PDF를 현재 운영 증명으로 제출하지 않습니다.

## 준비물

- 본인 명의의 서로 다른 성인 토스 시험 계정 A/B와 두 기기. 같은 계정 두 브라우저는 대체할 수 없습니다.
- 이어폰 두 개. 두 기기를 떨어뜨려 다른 사람의 음성이 마이크로 섞이지 않게 합니다.
- A/B에 실제 이용 가능한 포인트. 운영 가입 포인트를 사용하고 유료 충전은 필요할 때 본인이 진행합니다. 자동으로 결제하지 않습니다.
- 운영자 이메일로 관리자 로그인: https://honsulbar-app.vercel.app/?admin=1

## 1. 토스 로그인과 동의 (약 3분)

먼저 운영자 화면에 로그인해 새로고침합니다. 운영자가 24시간 확인하지 않아 걸린 자동 안전 점검은 이 실제 운영 확인으로 해제됩니다. 미처리 신고가 있으면 실제 검토·조치를 먼저 하고, 점검 기능을 강제로 끄지 않습니다.

1. 새 .ait 테스트 링크를 토스에서 엽니다. 토스 로그인·이름/생년월일 제공 동의 후 로비가 열려야 합니다. 취소하면 입장되지 않고 재시도가 가능해야 합니다.
2. 사진/닉네임을 등록하고 실제 얼굴 확인을 완료합니다.
3. 입장 전 음성 안내가 나와야 합니다. 체크하지 않으면 계속할 수 없어야 하고, 거부하면 포인트 차감 없이 로비·고객센터를 이용할 수 있어야 합니다.
4. 양쪽 모두 동의 후 같은 바에 입장합니다. 한쪽만 동의한 계정과는 음성 연결되지 않아야 합니다.

미성년자를 실제 시험에 참여시키지 않습니다. 만 19세 미만 거부는 서버 자동 검사와 정식 제공된 시험 수단으로 검증합니다. 앱인토스 전체가 성인 전용이라는 가정으로 검사를 제거하지 않습니다.

## 2. 음성 신고와 증거 (약 5분)

1. B의 마이크를 켜고 '혼술바 안전 기능 시험, 지금은 테스트입니다'를 5~10초 말합니다. A가 실제로 듣는지 확인합니다.
2. A가 B 프로필 → 신고를 엽니다. '상대 음성 최근 N초' 첨부가 보이고 20초를 넘지 않아야 합니다. 신고 화면을 여는 순간의 자료만 선택하므로 미리 오래 열어두지 않습니다.
3. 기타 사유와 '두 시험 계정의 안전 기능 시험'을 적고 음성 첨부를 선택해 접수합니다.
4. 즉시 서로 목소리가 끊기고 현재 방문은 유지되어야 합니다. 이후 한쪽이 나가면 상대가 있는 바에 재입장할 수 없어야 합니다.
5. 관리자 → 새로고침 → 해당 신고를 찾습니다. 접수 번호·방·좌석·첨부 여부·만료 시각을 확인합니다. 음성 열람 버튼으로 B의 시험 문장을 재생합니다. 짧은 음성은 참고 자료이며 화자/원본 자동 인증으로 표시되면 안 됩니다.
6. 관리자는 확인 중 → 답변 등록 → A의 알림에서 답변 확인까지 진행합니다. 답변에는 신고자 신원이나 음성 링크를 넣지 않습니다.

신고로 연결이 제한되므로 반복 음성 시험은 새로운 계정 쌍 또는 해당 관계가 없는 다른 시험 계정으로 진행합니다. 실제 계정에 영구 제재를 시험하지 않습니다. 24시간 제한 시험을 했다면 운영자가 해제하고 결과를 기록합니다.

## 3. 프라이버시와 실패 경로

- 설정 → 음성 안전 처리 동의 철회를 누르면 현재 방문·음성 연결이 종료되고, 다음 입장에 다시 동의가 필요해야 합니다.

- 새 계정 쌍으로 음성 첨부 체크를 해제해 신고합니다. 관리자에게 음성이 없어야 하며 신고·차단은 성공해야 합니다.
- 음소거 또는 앱 백그라운드 전환 직후에는 이전 버퍼가 삭제되어 첨부가 없을 수 있어야 합니다. 상대가 나간 경우 오래된 음성을 몰래 업로드하지 않습니다.
- 목소리가 들리는데 첨부가 계속 없다면 기기/토스 버전과 시간을 기록합니다. 해당 웹뷰의 오디오 처리 호환성을 확인하기 전 성공 체크하지 않습니다.
- 관리자 로그아웃 후 API에서 음성 열람이 거부되어야 합니다. 일반 이용자 토큰도 관리자 열람을 할 수 없어야 합니다.
- 운영 DB의 만료 시각을 임의로 변경해 실제 증거를 삭제하지 않습니다. 만료·암호화·변조 검사는 자동 테스트로 확인하고, 실제 7일 경과 건의 API 차단/유지보수 삭제 결과를 운영 기록에 추가합니다.

## 4. 메일·대응·재시도 (약 3분)

1. 관리자 '운영자 시험 메일 보내기'를 누릅니다(하루 3회). 업체 접수 문구 후 실제 메일함에서 제목의 연동 테스트 표시를 확인합니다.
2. 실제 시험 신고도 메일함에 도착하는지 확인합니다. 메일에는 본문·음성·사진이 없어야 합니다.
3. 접수 시각, 메일 도착, 운영자 확인, 조치, 이용자 답변 확인 시각을 기록합니다. 시험 메일 성공만으로 신고 흐름 전체를 완료 체크하지 않습니다.
4. '대기 알림 재시도'는 재시도 시각이 된 건만 시도합니다. 실패가 계속되면 발신자 인증·키·정기 작업을 확인합니다. '업체 접수'와 '수신함 도착'을 구분합니다.
5. 화면이 켜져 있을 때 미처리 건수가 15초마다 갱신되고, 새 신고 상세는 새로고침으로 확인합니다. 이 자동 확인은 운영자의 사건 확인 시각을 대신 갱신하지 않습니다.

## 5. 제출 직전

- A/B 양쪽 토스 로그인, 음성 동의, 사진 검증, 음성 연결, 신고 음성 재생, 첨부 없는 신고, 관리자 답변, 실제 메일 수신의 결과를 기록합니다.
- 실제 결제·환불 시험은 본인이 승인한 거래만 진행하고 주문·포인트·취소 내역의 일치를 확인합니다. 별도 시험 없이 환불 작동 완료라고 표시하지 않습니다.
- 개인정보 국외 처리 고지와 법정 사업자 전화번호·통신판매업 신고번호는 확인된 실제 값으로 마무리합니다.
- PDF 핵심 확인: 법인/담당 연락처, 24시간 신고 처리 운영 가능 여부, 20초/7일 음성 처리 범위, 자동 음성 AI 미적용 사실.
- 제출 PDF는 public/legal/honsulbar-monitoring-response-policy.pdf입니다. 자동 음성 탐지 항목 전체가 충족된 것처럼 체크하지 않습니다. 별도 외부 전사 서비스는 연결하지 않았습니다.
