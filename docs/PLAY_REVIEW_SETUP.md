# Play 심사 접근 설정

구현 완료, 기본 비활성. 일반 이용자의 성인·사진 확인을 우회하지 않는다.

1. 개인 운영 계정과 다른 전용 Supabase Auth 이메일 계정을 준비한다. 새 비밀번호 입력·저장은 사용자가 직접 한다. 이메일 확인이 필요하다.
2. 승인 후 20261105_play_review_account.sql을 적용하고 서비스 역할 또는 관리자 SQL에서 hb_prepare_play_review(Auth UUID, 확인된 전용 이메일)를 호출한다. 기존 소셜 소유 관계가 있으면 거절하고, 전용 빈 회원과 play-review 소유 관계만 생성한다. 재호출해도 회원을 중복 생성하거나 포인트를 지급하지 않는다. 성인·사진 확인은 false, 잔액은 0으로 시작한다.
3. 서버에 HB_PLAY_REVIEW_AUTH_USER_ID와 HB_PLAY_REVIEW_MEMBER_ID를 설정한다. HB_PLAY_REVIEW_ENABLED=1은 새 인증 경로이므로 최종 승인 후 활성화한다. 기본 OFF이며 미설정 상태에서는 버튼이 숨겨지고 API는 503을 반환한다.
4. 첫 화면의 App review sign-in에서 로그인한다. 비밀번호는 Supabase Auth로만 보내며 저장하지 않는다. 서버는 Supabase에서 토큰을 검증한 뒤 지정된 계정·play-review 소유 관계·제재 상태를 검사한다. 일반 가입처럼 미확인 회원도 로비·프로필 설정을 이용하지만, 정상 DB의 성인·사진 확인 입장 제한은 그대로 적용된다. 로그인 API가 확인 상태·잔액을 변경하지 않는다.
5. 실제 기기에서 전체 접근을 확인한 후 Play 로그인 세부정보의 비공개 입력란에 전용 계정과 영문 안내를 입력한다. 유료 기능 접근·검토할 콘텐츠도 준비해야 하며 이 로그인만으로 전체 기능 검증이 완료되지는 않는다.

Supabase Auth의 비밀번호 로그인 속도 제한을 적용한다. 기능 OFF는 새 로그인을 중단한다. 이미 발급된 서비스 세션은 일반 세션이므로 즉시 회수하려면 해당 전용 회원 세션 정리를 함께 한다. 개인 계정을 심사자에게 공유하지 않는다.
