# 혼술바 토스 로그인 설정 현황

## 현재 상태

- 토스 로그인 콘솔에는 이용약관과 개인정보처리방침 URL이 등록되어 있습니다.
- 웹앱은 아직 토스 인가 코드 교환, 사용자 정보 복호화, 서버 세션을 구현하지 않았습니다. 화면은 로컬 목업 상태입니다.
- `api/toss-unlink.js`는 연결 끊기 콜백 수신 코드입니다. 환경변수와 실제 배포, 콘솔 테스트를 마치기 전에는 연결이 완료된 것이 아닙니다.
- Supabase의 `toss_login_links`는 연결 상태만 기록합니다. 향후 프로필·결제·신고 등 실제 사용자 데이터가 서버에 생기면 회원 탈퇴 시 해당 데이터 삭제도 함께 연결해야 합니다.

## 연결 끊기 콜백

- URL: `https://honsulbar-app.vercel.app/api/toss-unlink`
- 메서드: `POST`
- Basic Auth 헤더 입력란: `username:password` 형태의 충분히 긴 임의 값. `Basic ` 접두어 또는 Base64 인코딩값을 입력하지 않습니다.
- Vercel Production 환경변수 `TOSS_UNLINK_BASIC_AUTH`: 콘솔에 입력한 값과 동일하게 Secret으로 설정합니다.
- Vercel Production 환경변수 `SUPABASE_SERVICE_ROLE_KEY`: Supabase의 `service_role` 키를 Secret으로 설정합니다. `VITE_` 접두어를 붙이지 않습니다.
- Supabase URL은 기존 `VITE_SUPABASE_URL`을 사용하거나 `SUPABASE_URL`을 설정합니다.
- 세 환경변수 설정 후 Vercel 재배포와 토스 콘솔의 `테스트하기` 성공을 확인합니다. 키 자체는 GitHub, 채팅, 로그에 넣지 않습니다.

콜백은 Basic Auth를 확인하고 사용자 키가 `0`인 콘솔 시험 요청은 저장하지 않습니다. 실제 `UNLINK`는 연결 상태를 해제하고, `WITHDRAWAL_TERMS`·`WITHDRAWAL_TOSS`는 링크 기록을 삭제합니다. 현재 앱에는 서버 세션과 회원 데이터가 없으므로, 실제 토스 로그인 출시 전에 이 콜백을 세션 무효화 및 모든 회원 데이터 삭제와 통합해야 합니다.

## 동의 항목

- 이름: 콘솔 기본 필수 항목 유지. 앱 공개 이름은 별도로 설정한 닉네임을 사용합니다.
- 생년월일: 만 19세 이상 입장 제한을 서버에서 검증하기 위해 필수 동의로 추가합니다. 개인정보처리방침에도 그 목적을 명시합니다.
- 이메일, 성별, 내·외국인 정보, 휴대전화번호, CI: 현재 기능에 직접 필요하지 않아 사용 안 함을 유지합니다. 성별은 앱 프로필에서 선택합니다.
- 마케팅 정보 수신 동의: 광고성 알림을 실제 발송하기 전까지 등록하지 않습니다.

## 남은 로그인 구현

토스 앱에서 인가 코드를 받은 뒤 서버에서 mTLS를 사용해 토큰을 교환하고, 사용자 정보를 복호화하여 생년월일로 연령을 검증해야 합니다. 복호화키는 서버 비밀값으로만 보관하고 클라이언트나 GitHub에 넣지 않습니다. 토큰·세션 저장, 재로그인, 로그아웃, 회원 탈퇴, 콜백 후 재진입 동작까지 연결하고 실제 토스 앱에서 시험해야 합니다.
