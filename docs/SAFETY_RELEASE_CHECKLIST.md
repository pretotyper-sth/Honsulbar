1. 실제 카메라로 사진 일치·불일치·화면 재생·재촬영을 시험합니다. 자동 검사 오탐·지연을 확인하기 전 출시하지 않습니다.
2. 운영 DB 백업 후 20261012_safety_automation.sql → 20261014_report_triage.sql → 20261016_face_verification.sql 순서로 적용. 기존 회원은 사진 재검사, 현재 입장은 퇴장 처리하되 남은 시간 보존. 상품·포인트 잔액을 초기화하지 않습니다.
3. 서버 전용 HB_IDENTITY_HASH_KEY(32자 이상)를 운영 환경에 등록한 뒤 API·앱을 함께 배포합니다. 키는 바꾸면 기존 제재 키가 달라지므로 별도 비공개 백업하고 로그·문서·저장소에 넣지 않습니다.
4. 운영 환경의 관리자 OTP 메일·긴급 알림 도달·신고 처리·제재·탈퇴 삭제·보유기간 자동 삭제를 시험합니다. Resend가 없으면 이메일이 발송된다고 주장하지 않습니다. 관리자 실제 확인은 대체할 수 없습니다.
5. Vercel 처리 지역·로그 보유·해외 재위탁 범위와 Supabase/메일 처리 계약을 확인해 개인정보처리방침의 국외 이전 국가·항목·시점·방법·목적·보유기간을 확정하고 적법한 공개/동의 절차를 적용합니다. 서울 DB만으로 모든 국외 이전이 없어지는 것은 아닙니다. Vercel API 서울 리전 설정은 준비됐으나 배포 전입니다.
6. 사업자 정보의 실제 전화번호와 필요한 통신판매업 신고 정보를 확인해 공개 사업자 정보에 반영합니다. 가족 법인의 명의 사용·사업자 증빙은 실제 권한과 콘솔 정보가 일치해야 합니다.
7. 최신 정책·검증 결과·실제 기능 설명으로 사전검수 요청. 토스 로그인 실명 인정 및 음성 미저장·미탐지 허용 여부는 답변 전 충족으로 체크하지 않습니다. 비용이 확인되지 않은 인증 상품을 무료로 가정하거나 계약하지 않습니다.

## 제재 식별자 최소 보관 판단

목적은 반복 위반자가 탈퇴 후 같은 토스 계정으로 즉시 복귀하는 것을 제한하여 이용자를 보호하는 것입니다. 계정 삭제만으로 제재 이력을 모두 지우면 동일 계정의 회피가 가능하므로 원문 이름·CI·생년월일 대신 서버 비밀키로 만든 HMAC과 제재 만료/삭제 시각만 분리 보관합니다. 이 값도 개인정보입니다. 기간 제한 종료 후 1년, 영구 제한 등록·변경 후 3년으로 제한하고 자동 삭제 및 삭제·이의 제기 창구를 둡니다. 이 기간은 법정 의무 기간이나 토스 승인 기준으로 확정된 값이 아닙니다. 실제 재발 빈도·민원·필요성을 검토하여 단축하고 필요성이 사라지면 삭제합니다. 운영 중 실제 평가·접근통제·파기 결과를 기록해야 하며 문서 작성만으로 적법성이 확정되는 것은 아닙니다.

## 법인과 담당자의 역할

서비스 제공·약관상 업무 주체는 상지컴퍼니 주식회사, 김정수는 회사의 업무 담당자입니다. 개인 보증·개인 배상 약속은 두지 않습니다. 위법 행위, 고의·중대한 과실에 대한 책임까지 약관으로 배제할 수 있다고 안내하지 않습니다. 사전검수 안내만으로 책임을 면제받는 것도 아닙니다.

## 배포 요청 시 정책 마무리

배포를 진행하는 에이전트가 처리한다. 사용자에게 초안 삭제를 별도 요청하지 않는다. 최초 정식 배포 시 모니터링 정책을 버전 1.0으로 확정하고 한국 시간의 실제 시행일을 기입한다. 이후 배포에는 기존 시행일을 임의로 덮어쓰지 않는다. 공개 HTML과 PDF를 함께 갱신하고 초안 표시가 없는지 확인한다. 공개 담당 표시는 혼술바 운영 담당·이메일을 기본으로 하며, 실제 법정 사업자 정보와 비공개 심사 담당자는 허위 이름으로 대체하지 않는다. 전화번호 등 법정 사업자 표시의 미확정 사항도 출시 전에 확인한다. 배포 검사는 미완료 초안을 발견하면 업로드·운영 빌드를 중단한다.

법정 사업자 정보의 실제 법인명·대표자명·사업자등록번호·사업장 주소와 확인된 전화번호·통신판매업 신고번호는 간소화·가명 처리 대상에서 제외한다. 개인정보 보호책임자와 청소년 보호 정책의 책임자 표시는 실제 담당 김정수로 유지한다. 일반 안내·문의의 운영 담당 표기만 간소화한다. 미확정 전화번호·신고번호를 임의 생성하거나 이메일로 대체 완료 처리하지 않는다.

## 2026-10-14 신고·차단 시험 가이드

신고·차단 자체는 강제 퇴장이 아니다. 현재 방에 양쪽이 그대로 남고 즉시 서로 음성을 전달하지 않는다. 1:1 연결·요청도 끊는다. 방을 나온 뒤 상대가 있는 방으로 입장·재입장하지 못한다. 운영자의 별도 제재·긴급 안전 점검에 의한 퇴장은 구분한다. 신고와 독립 차단 모두 방문 유지·연결 제한을 자동 검사했다.

실기기 시험은 서로 다른 시험 계정 A/B를 같은 바에 입장시켜 진행한다. 스피커 피드백을 피하려면 이어폰을 쓴다. B가 말할 때 A가 듣는 것을 확인하고, A가 B를 신고한다. 양쪽이 자동 퇴장하지 않고 서로의 소리가 끊기는지 확인한다. A가 나간 뒤 B가 있는 바 재입장을 시도하면 거절되어야 한다. 독립 차단은 새 시험 계정 쌍으로 반복한다. 영구 제재는 실제 이용자에게 시험하지 않는다.

신고 알림 시험은 운영 메일·발신자 인증·관리자 로그인이 설정된 시험 환경에서 진행한다. 설정 전에는 메일 수신을 성공으로 체크하지 않는다.
1. A가 B를 대상으로 제목 식별이 가능한 시험 신고를 1건 접수한다. 일반 신고와 긴급 사유 신고는 구분한다.
2. 운영 이메일에서 새 문의 번호가 포함된 메일을 확인한다. 긴급 사유는 긴급 신고 제목이어야 한다.
3. 관리자 화면에서 해당 번호·신고자·대상·사유·신고 당시 방 정보를 확인하고 확인 중 상태로 바꾼다.
4. 시험 답변을 등록하고 A의 앱 알림과 답변 내용을 확인한다.
5. 접수·메일 수신·운영 확인·답변 시각과 결과를 기록한다. 메일 누락이나 관리자 접근 실패가 있으면 대응 체계 완료로 체크하지 않는다.

토스 공유는 자동 전송으로 구현된 기능이 아니다. 담당자가 콘솔의 공식 문의·상담 경로로 사건 식별자, 발생·인지 시각, 위반 유형, 영향 범위, 보호·제재 조치와 추가 지원 요청을 보고하는 운영 절차다. 일반 보고에는 얼굴 사진·음성 원본·사용자 실명 등 불필요한 개인정보를 첨부하지 않는다. 토스가 별도 사고 접수 경로를 안내하면 해당 경로를 따른다. 신고 알림 시험과 달리 토스에 실제 위반 신고를 테스트로 발송하지 않는다.
